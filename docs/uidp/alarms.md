# 工程数据点、枚举与报警

[v0.9 使用手册](../guide.zh.md) · [UIDP 工程格式](../uidp-format.md)

在设计器顶部点击「数据与报警」，或点画布空白处，在工程属性打开「工程数据与报警」。数据点、表达式和报警由每个运行中的工程统一管理，报警栏与报警列表显示和操作同一份状态。一次报文中的相关数据点更新后，再求值依赖它们的表达式和报警。

[从数据点到历史筛选的实训](../guide.zh.md#工程数据与报警)

## 数据点

「设备数据」复用已有的绑定设置。选择来源连接和子通道，再配置键值、JSON、HEX、CAN 信号、Modbus 或 S7 地址。可以在控件绑定中点「存为工程数据点」，也可以在文本、JSON 或 HEX 解析预览中选中字段后保存。Modbus 和 S7 工程点持续后台采集，切换页面仍会更新。

一个设备点需要唯一来源。同一连接收到多个客户端或 Topic 的同名数据时，点显示「来源不唯一」。分别指定来源后，可用计算点汇总。设备点可选「数据有效时间(ms)」，`staleAfterMs` 为 0 表示不限。失联或超时会标为「旧值」，换算失败会标为「换算失败」。运行预览的「工程数据监视」显示最近有效值、数据质量、来源和采样时间。记录、公式、报警、发送只使用有效值。

「工程参数」定义待输入的值。选择数值、布尔或文本类型并填初始值，输入框在属性里选择该参数。运行时修改输入框，回车或离开输入框后更新共用值。按钮或其他绑定也能选择同一参数。工程文件的初始值用 `initialValue` 保存，例如 `{"name":"Kp","initialValue":1.25}`。运行值随当前运行实例保留。布尔参数用于发送时按 1 或 0 编码。

「计算表达式」使用 `T["数据点名称"]` 引用其他点，可使用算术、比较、位运算与 `and / or / not`。例如三个故障点 `L1`、`L2`、`L3` 的总故障：

```text
T["L1"] or T["L2"] or T["L3"]
```

控件和曲线选择解析模式「工程数据点」，在绑定字段下拉框中选择或搜索数据点名称，也可手动填写。多个连接即使都有 `fault` 字段，也应分别定义数据点并选择明确的来源连接。缺失、无效或断开的输入保持未知，不当作零。工程表达式的 `and / or` 返回布尔汇总：`故障 or 未知`、`未知 or 故障` 都为真；`正常 or 未知` 保持未知，不伪造恢复。`and` 有已知假值时为假，其余无法判断的组合仍未知。算术表达式仍需要相关输入有效。表达式按依赖关系排序，保存时拒绝循环引用和不存在的点。普通绑定的 `value * 0.1` 及原有单点 `and / or` 行为保持不变。

工程根节点 `logic` 示例：

```json
{
  "id": "pump-station-01",
  "soundEnabled": false,
  "points": [
    {"name": "L1", "binding": {"parseMode": "键值匹配", "sourceCardId": "PLC_A", "key": "fault"}},
    {"name": "L2", "binding": {"parseMode": "键值匹配", "sourceCardId": "PLC_B", "key": "fault"}},
    {"name": "总故障", "expression": "T[\"L1\"] or T[\"L2\"]"}
  ],
  "alarms": [
    {"id": "系统故障", "condition": "T[\"总故障\"] != 0", "level": 3, "ackRequired": true, "text": "检查故障设备"}
  ]
}
```

双击数据点名称可重命名，计算表达式、报警条件以及所有控件和曲线（包括暂未显示的曲线）的工程数据点引用会同步更新。名称不能为空或重复；原始设备字段、控件标题和报警文字保持原意。点击「确定」统一提交，取消不改变工程，整次修改可一次撤销。

选中数据点后可「查看引用」，核对控件、曲线、记录列、发送输入和报警。简单报警可用「按阈值生成条件」，选点后输入比较运算和阈值。用「表达式试算」填入样例值，检查条件结果。

`logic.id` 用于区分本机历史，界面首次配置时自动生成。重命名连接卡片会同步更新数据点的来源引用。跨工程复制控件时，需要在目标工程配置同名数据点；保存会检查缺失引用。

## 报警状态与历史

每条报警包含唯一名称 `id`、条件 `condition`、级别 `level`（1～3，3 最高）、确认要求 `ackRequired`（默认开启）和文字 `text`。

- 条件从假变真：产生一次触发事件，重置本次确认和消音状态。连续真值不会重复报警。
- 条件从真变假：产生恢复事件。需要确认的报警如果尚未确认，仍保留在当前列表。
- 确认：只确认软件中的报警，不向设备写入。故障仍存在时继续显示活动状态。
- 消音：停止当前报警的声音提醒，不清除故障。再次触发时恢复提醒。
- 数据未知：保留已有活动状态，标明未知；不伪造恢复事件。

`AlarmBanner` 显示活动数、未确认数、最高级别及最新报警，并提供确认全部、消音。`AlarmList` 支持当前/历史切换、确认所选、确认全部、消音和 CSV 导出。触发事件也显示通知飞窗。`soundEnabled` 开启时使用系统提示音；未要求确认的报警使用消音停止声音。

最近 2000 条触发、恢复、确认和消音事件按工程标识保存在应用本地数据目录的 `alarms` 子目录。同一工程的运行实例在后台合并各自新增的记录。重新运行可查看历史，当前状态由新收到的数据重新计算。历史 CSV 带 UTF-8 BOM。新记录使用含毫秒的 UTC 时间，结尾为 `Z`。已有无时区的记录按本地时间读取。

### 列表筛选

点击「筛选」可设置名称／报警文字关键词、1～3 级、当前状态或历史事件，以及最近 1 小时／24 小时／7 天或自定义起止时间。条件组合生效。当前报警按触发时间、历史按事件时间比较。自定义范围用本地时间，包含所选开始秒和结束秒的全部记录。无时间戳的未知报警只在「不限时间」下显示。

自定义范围将日期和时间分开显示。日历图标打开 Fluent 日历，时间图标打开时／分／秒滚轮，确认后应用，取消保留原值。两个输入框也支持键盘输入，按 Enter 或移开焦点后生效。空间不足时在独立 Fluent 窗口中显示同一组条件，报警表保持原来的尺寸。该筛选仅影响当前列表。

筛选区默认收起。收起后条件仍有效，按钮显示有效条件数。「重置筛选」恢复全部显示。当前报警页提供「确认所选」「确认全部」和「消音」，选中的报警被过滤掉后会清空选择。历史页按「事件」展示记录，可选择「导出筛选结果」或「导出全部历史」。

已保存工程的预览和导出的应用各自记住每张报警列表上次选用的「当前报警」或「历史记录」。筛选条件用于当次查看。

## 枚举显示

`NumericDisplay` 的 `displayFormat` 选择 `"枚举"`，`textList` 每行一个数值、文字和可选颜色：

```text
0=停止
1=运行|#107c10
2=故障|#d13438
```

颜色格式为 `#RRGGBB`。数值必须唯一。未匹配时显示原值，或设置 `unknownText`；`unknownColor` 默认红色，留空使用主题强调色。枚举仅影响显示，不修改原始点值或设备写入。

`displayStyle` 选择 `"状态徽标"` 可用紧凑胶囊显示上述状态；标题位于徽标旁，映射色仍是文字颜色，背景随主题生成。省略该属性仍使用原数值卡片布局。

在属性面板点「编辑枚举」即可逐行编辑数值、文字和颜色。输入预览值可查看实际显示效果。「另存为工程枚举」把当前表保存在工程中，其他小灯和数值徽标可以选用它，在任一处修改表内的文字或颜色会同步到引用它的控件。

例如在工程顶层配置一张命名表，并让两个控件的 `properties.enumTable` 都填 `泵状态`。

```json
{
  "enumTables": {
    "泵状态": "0=停止|#808080\n1=运行|#008040\n2=预警|#e0a000\n3=故障|#d13438"
  }
}
```

小灯的 `stateMode` 选 `多状态`，`ledEffects` 可设为 `{"0":"off","1":"steady","2":"slow","3":"fast"}`。省略的灯效为常亮，慢闪和快闪的完整周期分别为 1 秒和 0.5 秒。灯效属于各自的小灯。绑定完整的数值状态码后，小灯和徽标按换算后的数值匹配，连续收到同一个值会保持闪烁节奏。未定义的码显示未知状态和原值，通信过期时小灯熄灭。单个小灯也可以在本地 `textList` 配置映射。

## 工程兼容

原有开关量小灯沿用原工程格式，数值显示的本地枚举沿用 UIDP 1.3。多状态小灯和工程枚举表使用 UIDP 1.4。[UIDP 格式与旧工程升级](../uidp-format.md#从旧版升级)
