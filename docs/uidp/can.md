# FluentHMI Studio 的 CAN 总线

[v0.9 使用手册](../guide.zh.md) · [CAN 位图实训](../tutorials/can-bit-map.zh.md) · [UIDP 工程格式](../uidp-format.md)

`CanConfigCard` 连接一路 CAN。`defaultAdapter` 可选 `"PCAN"`、`"ZLG"`（另设 `zlgModel`）、`"SocketCAN"`、`"slcan"` 和 `"虚拟 CAN"`。`defaultBitrate` 如 `"500k"`。物理 CAN FD 使用 `canFd: true` 和数据域速率 `defaultDataBitrate`。DBC 文件写在 `dbcFile`，路径相对于工程，Studio 导出时会复制文件。

桌面版「虚拟 CAN」在本卡回环已发送的帧，可验证标准帧、扩展帧、RTR、CAN FD 和信号解析。实际总线位时序、仲裁、负载及物理适配器需要实机验证。[17.7 CAN 教程](../tutorials/17-frame-io.zh.md#177-can-经典帧与-fd-信号)

CAN 报文监视、CSV 和 DBC 信号解析都以单帧为单位。经典 CAN 单帧最多 8 字节，CAN FD 单帧最多 64 字节。ISO-TP、J1939 TP 或设备自定义的多帧消息可逐帧查看与记录，完整消息的收包重组、发送分包和流控需要对应的传输协议支持。

新建连接卡片按可见配置行确定高度，切换完整或简洁模式时按内容整理。工程中保存的手动高度继续保留。连接状态显示在卡片顶部，连接后在底部显示收发计数。连接失败的原因通过应用内通知显示，也可在匹配连接的通信日志中查看。

## 字段帮助

设计器中，发送初值映射及反馈间隔、DBC/CAN 信号、接收过滤、采样点/自定义位时序，以及 CAN 发送模式下的报文、发送模板和循环周期旁有圆形信息按钮。点击可打开详细说明与填写示例。选择「复制示例」后，将内容粘贴到对应字段。长内容可滚动，支持中英文、关闭按钮和 Esc。

运行时的 ZLG 自定义时序行、报文监视模式选择旁也提供同样的帮助，预览和导出应用均可查看。发送初值帮助明确区分连接卡片上的 `HMI=IO` 和开关的 `B4b4={value}`，并说明只有首次发送使用反馈初始化，后续沿用发送缓存。

## ZLG 采样点与自定义位时序

选择 ZLG 后，卡片显示「自定义」输入框。设计器的 `zlgCustomTiming` 设置其初始值，`zlgSamplePoint` 设置默认采样点。连接前可以修改，连接后锁定。输入自定义时序时，波特率和采样点下拉框停用。清空后恢复所选采样点或设备标准波特率。

USBCAN-I、I+、I-mini、II、II+ 使用 16 MHz 晶振，位时序公式的时钟为 8 MHz。自定义留空、采样点选「设备标准」时沿用原厂表，例如 800k 对应 `00,16`，1M 对应 `00,14`。手动选择百分比后按目标值计算，SJW 为 1，卡片「时序」显示实际可实现值。例如 500k、87.5% 对应 `00,1C`，500k、75% 对应 `00,3A`。800k 请求 87.5% 时实际为 90%。也可以填写以下任一格式。

- 十六进制 `BTR0,BTR1`，如 `00,1C` 或 `0x00,0x1C`；BTR1 的三次采样位原样保留。
- 十进制 `BRP,TSEG1,TSEG2,SJW`，如 `1,13,2,1`；可设标准列表之外的有效速率。
- 此型号的 ZCANPRO 完整计算结果，如 `500Kbps(87%),(00,1C)`。实际速率和采样点按寄存器计算，括号中的整数百分比可能经过取整。

「自定义」旁的「计算」可打开内置位时序计算器，适用于上述 USBCAN-I/II 系列，无需安装 ZCANPRO 或连接 CAN 卡。输入目标速率（如 `500k`、`1M` 或十进制 bps）、目标采样点、SJW、最大速率误差（默认 0.1%），可选择单次或三次采样。结果列出实际速率、采样点、速率误差、BRP/TSEG/SJW 和 BTR，优先显示速率误差最小、采样点最接近的组合。500k、87.5%、SJW=1 的首项是 `00,1C`。

选中结果后点击「应用到卡片」会回填当前卡片的自定义输入框，点击「连接」才会配置硬件。若要保存为工程默认值，可复制结果到设计器的 `zlgCustomTiming` 属性后保存工程。「复制参数」只复制选中结果，取消保留原配置。连接期间不能打开计算器。其他型号通过下表的格式粘贴厂商计算器结果。

其他 ZLG 型号使用官方 SDK 的 `通道号/baud_rate_custom`，在初始化通道之前设置；自定义设置成功后不再发送标准速率覆盖它。各型号的寄存器格式不同，请在 ZCANPRO「工具 → 波特率计算器」中选择实际型号，设置速率、采样点并复制完整结果：

| 型号 | `zlgCustomTiming` 示例与格式 |
| --- | --- |
| USBCAN-E-U、2E-U | `1.0Mbps(72%),(004B0001)`，单个寄存器值 |
| USBCAN-8E-U | `1.0Mbps(62%),(00,23)`，两个寄存器字节 |
| USBCAN-4E-U | 十进制 bps，如 `200000`；此型号的接口不提供独立采样点设置 |
| USBCANFD-100U-mini、100U、200U、400U | `1.0Mbps(75%),5.0Mbps(75%),(60,0080040D,00800001)`，时钟及仲裁/数据域寄存器 |
| USBCANFD-800U | `250Kbps(87%),1.0Mbps(75%),(13,2,2,10,5,2,2,5)`，八个型号专用参数 |

表中为官方 SDK 的格式示例，使用时应替换成目标总线的参数。CAN FD 型号的完整计算结果包含两个域，在经典 CAN 模式下也保留完整格式。HMI 不把 PCAN 的 BRP 参数或其他型号的寄存器格式转换成这些私有格式；格式不匹配会在连接前报错，驱动拒绝时会报告失败，不退回标准速率。其他型号的采样点下拉框保留停用，通过计算器结果指定采样点；自定义留空仍使用原有设备标准速率。

格式及调用顺序依据[致远官网下载页](https://www.zlg.cn/can/down/down/id/22.html)中的 [CAN(FD) 接口卡 SDK](https://www.zlg.cn/data/upload/software/Can/CAN_lib.zip)（接口函数手册 V1.21、设备属性 XML），BTR0/BTR1 依据 [CAN 测试软件与接口函数使用手册](https://www.zlg.cn/data/upload/software/Can/CAN_test_um.pdf)。驱动 DLL 不随应用分发，仍沿用原有的 `zlgcan.dll` 和整个 `kerneldlls` 文件夹。

## 信号键与 DBC

在 CAN 配置卡的「CAN 信号」打开「可视化编辑…」，选择报文 ID 后查看位图。点信号行定位到对应位，粘贴 HEX 数据或形如 `102#0000DC05` 的样例即可看到解析值。DBC 定义在这里可查看。添加或编辑内联信号时，可以点击位图指定起始位，其定义保存在卡片的 `canSignals` 中。

在工程数据点、实时曲线或数字时序图的逐路绑定中，选择「CAN 信号名称」，再按来源连接、报文 ID 和信号选取。使用 `报文名.信号名` 引用 DBC 信号，使用 `0x102.EngSpeed` 这种带报文 ID 的键引用内联信号。已有的短信号名可继续使用。「键值匹配」还可以读取 DBC `VAL_` 提供的 `.text` 描述。

```text
102 EngSpeed : 16|16@1+ (1,0) [0|8000] "rpm"
```

上例的 ID 是十六进制 `102`。`@1` 为 Intel，`@0` 为 Motorola，`+` / `-` 表示无符号 / 有符号。

## 按位取值

设计器中选「CAN 按位取值」后打开「可视化编辑…」。可在位图点选起始位、编辑长度和字节序，再粘贴一条样例核对解析值。工程数据点、显示控件、实时曲线和逐路绑定的时序图使用同一个编辑器。[分步操作](../tutorials/can-bit-map.zh.md#在工程数据点上按位取值)

`parseMode` 选 `"CAN信号"` 时，`canId` 为十六进制报文 ID，`canStartBit` 为起始位，`canBitLength` 为 1–64。`canByteOrder` 可选 `"Intel"`（默认）、`"Motorola MSB"`（DBC 的 `@0`）或 `"Motorola LSB"`（起始位是最低位）。`canSigned`、`canFactor`、`canOffset` 默认分别为 `false`、1、0。

上述取值字段在绑定和曲线里的写法，以及取值后的换算，见[取值与曲线](data.md)。

## 发送与监视

`commandMode` 选 `"CAN"`，`canId` 填 DBC 报文名或 ID。在 `commandTemplate` 里写逗号分隔的 `信号=值`，`{value}` 取控件的当前值。信号值可以是十进制物理量、值描述或 `0x` 原始码。无信号的报文可按 HEX 模式组字节。`canCycle` 大于 0 时按指定毫秒周期重发，0 时使用 DBC 的 `GenMsgCycleTime`（缺省时发一次）。

按信号发送（如 `Flag={value}`）会保留同一连接中、同 ID 最近一次由 HMI 发送的其他位。首次发送或断开重连后的首帧，从各信号的 `GenSigStartValue`（缺省为 0）初始化；接收报文不会自动成为发送基准。因此这不是设备级的位写入命令：若要保证设备当前其他输出不变，须依据设备协议提供完整的初始控制状态，或使用协议规定的写入有效位／掩码，不能只靠接收绑定字段推断。

需要从反馈初始化时，可在 CAN 卡片的 `canTxInitialState`（发送初值映射）中每行写一条规则，并重连。留空保持原有行为。这是各适配器共用的 CAN 配置，不限定 DBC、节点名或 CAN ID，支持以下两种写法：

- `目标报文=反馈报文`：复制同名信号。例如 `HMI=IO`，适用于两个报文的输出控制与反馈使用相同信号名。
- `目标报文.控制信号=反馈报文.状态信号`：逐个指定对应关系，例如 `Control.Red=Status.RedFeedback`。不同名称、不同位位置和不同字节序均可映射；可写多行，从多个反馈报文初始化同一个控制报文，也可用十六进制 ID 引用内联信号。

来源与目标须有 DBC 或内联信号定义；映射字段的位长、符号、数值类型、比例、偏移和单位须一致，不自动猜测业务含义或换算不同编码。目标位不能重复或重叠。其他字段保留目标报文的 DBC 初值，不整帧复制输入或协议头。配置前须确认映射的反馈确实表示对应控制的当前状态；脉冲、翻转或仅置位的控制协议不能据此推断。设备已周期广播反馈时直接接收即可，无需主动查询。

启用后，首次按信号发送前必须收到覆盖全部映射信号的有效反馈。`canTxInitialMaxAge`（初值反馈最大间隔）默认 2000 ms，从适配器读到报文时的单调时间开始计时，包含后台队列和界面交付的等待；没有反馈、反馈过期或被接收过滤器排除时拒绝发送，不回退为全零。错误帧、远程帧、错误帧格式及缺少映射字段的数据不更新基准；未映射的尾字节可省略，不合并不同长度的报文。DBC 指定的经典/FD 格式须匹配；仅内联定义且字段不超过 8 字节时，两种数据帧均可作为反馈。首次发送成功后仍使用本连接的发送缓存，避免滞后的反馈覆盖刚发出的控制；重连清空并重新等待反馈。此机制不会持续同步其他控制器后续改变的输出，也不作用于原始整帧发送。

slcan 使用适配器对发送的应答来确认映射报文。旧固件若在连接时没有串口应答，仍可普通收发；发送初值映射需要支持应答的适配器。连接后发生应答超时时，重新连接可清理待发送任务。

下面的滑块每 100 ms 发送一次 `PC2BLDC`，向控制器写入设定转速。

```json
{"type": "Slider", "id": "speed", "geometry": {"x": 420, "y": 60, "w": 260, "h": 36},
 "properties": {"maximum": 4000, "sendOnChange": true, "commandMode": "CAN", "canId": "PC2BLDC",
                "commandTemplate": "SetMotorSpeed={value}, SetDerect=1", "canCycle": 100}}
```

手工发送原始报文时，选中数据发送卡片，在「操作与发送」把「数据格式」选为「CAN」，再选择目标 CAN 连接。运行时输入 `123#1122` 并发送，向标准 ID `0x123` 发送 `11 22`。需要在运行时确认目标和报文内容，可开启下发确认与详情。[发送预览与下发确认](commands.md#发送预览与下发确认)

`CanMonitor` 的 `displayMode` 可选 `"按 ID 汇总"`（默认）或 `"滚动日志"`。汇总模式在各连接内按 ID、标准/扩展格式和收发方向合并，显示最新数据、平均周期与次数；滚动模式按到达顺序逐帧追加，显示报文时间，隐藏「周期」「次数」列，并禁止排序。切换到滚动模式时保留各汇总项的最新一帧，后续报文逐帧记录；切回汇总时合并保留的记录，恢复「周期」「次数」列和排序。

切到其他页面时，监视器仍接收报文并按保留行数更新，启用的自动保存继续写入。回到报文页时，表格会调整可见行的高度，滚动模式按「自动滚动」设置跟随最新报文。

最左侧「序号」按进入监视器的收发报文累计，从 1 开始。滚动日志在淘汰旧记录、筛选或排序后保留原序号，不重新编号；汇总模式显示该 ID 最近一次更新对应的序号，与「次数」不同。切换显示模式保留编号，清空或首次 CAN 连接触发清空后重新从 1 开始。

`maxMessages`（「显示行数」）设置表格最大保留条数，默认 1000，范围 1–50000。滚动模式移除最早记录，汇总模式保留最近更新的 ID。运行时也可以切换模式、修改条数上限。`autoScroll`（默认 `true`）仅适用于滚动模式。勾选时，向上翻阅会暂停跟随，回到最底部时恢复。汇总模式隐藏「自动滚动」，设计器属性面板也按模式显示；切换模式保留此前的勾选状态。时间、序号、筛选、条数上限和导出两种模式均可使用。

运行预览和导出的应用各自记住每张监视器的显示模式、显示行数和自动滚动。首次运行采用工程默认值。ID 与帧类型筛选用于当次查看。

点击保存图标或右键选择「导出报文」，将当前筛选和排序后的保留记录导出为 UTF-8 CSV。第一列 `sequence` 是与表内一致的整数序号；第二列 `time` 是带日期、毫秒和时区的本地时间，例如 `2026-11-17T13:14:35.843+08:00`；最后仍保留整数 `timestamp_ms` 列供程序处理。其余列包括 ID、收发方向、帧类型、长度、完整数据、报文名，以及开启「显示信号」时的解码值。汇总模式另外导出 `period_ms` 和 `count`；滚动模式省略这两列，与界面一致。CAN FD 的 64 字节数据完整导出；清空或超出上限移除的记录不包含在导出中。预览和独立导出应用均支持这些功能。

`DataSendCard` 可发 `ID#数据`，如 `102#11223344`。[可运行的 CAN 工程](../../examples/tutorials/12-CAN收发测试.uidp)和[它的 DBC](../../examples/tutorials/12-CAN收发测试.dbc)应放在同一目录。

## 多通道与自动保存

绑定、曲线、发送命令及监视器均可选具体连接卡，参见[连接与子通道](data.md#连接与子通道)。汇总键包含连接会话、CAN ID、标准/扩展格式与收发方向；不同连接的同 ID 报文不会合并。表格增加「连接 / 通道」，CSV 增加 `connection_id` 与 `channel`。

监视器的「自动保存」记录所选来源的全部收发帧，与显示模式、ID/类型筛选、清空及淘汰行无关。先选目录（可通过 `autoSaveDirectory` 预设），每个 CSV 达到「每文件行数」（`autoSaveRows`）即新建下一份。新控件默认 100000 行，范围 1–1000000；0.8 之前版本保存的工程缺少此字段时沿用原 `maxMessages`（未设置时为 1000），首次读入后两项独立。修改「显示行数」仅影响表格；修改「每文件行数」会保存当前尾段，再按新值分段。关闭保存、断开最后一个所选 CAN 连接、退出运行会写完最后不足分段行数的文件。重新连接继续新的一组文件，不覆盖旧文件；默认不自动删除。`autoSave` 默认关闭，0.8 之前版本保存的工程不会自动启用此功能。磁盘写入失败或持续跟不上流量时停止保存并提示未确认保存的帧数，通信不停止。

CAN 原生驱动的打开、停止接收线程与关闭在后台会话执行，界面显示连接/断开进行中。ZLG 同一设备的不同通道共享设备句柄，重复占用同一路会被拒绝，最后一路断开才关闭设备。驱动本身长时间不返回时，界面保持可用，释放操作仍等待驱动返回；不强行终止正在访问驱动的线程。

运行时勾选「自动保存」后，文件夹按钮显示当前目录，可打开或更换。更换时旧目录的尾段写完，后续报文进入新目录。连接卡片按型号显示位时序和 FD 选项，使用「简洁」且启用了 FD 时仍可查看当前时序摘要。

## 设备识别、自动恢复与负载

- PCAN 通过厂商驱动列举通道；ZLG 卡片型号旁的搜索按钮在后台读取 Windows 已连接 USB 设备的驱动名称。找到多个型号时选择一个；同型号多台设备仍需核对设备索引。兼容卡未提供明确型号时保留手动选择，不根据通用 USB 芯片 VID/PID 猜测型号。
- USBCAN-E-mini 使用 USBCAN-E-U 的类型号 20 和单通道 EU 配置。依据：[官方用户手册 §1.1](https://www.zlg.cn/data/upload/software/Can/USBCAN-E-mini_um.pdf)明确说明两者兼容；仍需实卡确认第三方兼容驱动行为。
- 属性 `autoRecover` 默认 `false`。开启后 PCAN 使用官方 [BusOffAutoReset](https://www.peak-system.com/documentation/API/PCAN-Basic.Net/html/0a342681-5ade-4a4f-9bec-3a04f790f37b.htm) 参数；ZLG 在该通道的接收线程中每秒尝试 ResetCAN / StartCAN，其他通道保持打开。它不处理拔线、USB 设备消失。SocketCAN 需执行卡片提示的 `restart-ms 1000` 系统命令；slcan 不提供此开关。
- 收发计数旁的「估算负载」按本通道成功采集的收发帧、帧格式、数据长度和位填充上限估算，每秒更新，CAN FD 的 BRS 数据段按数据域速率计算。卡片接收筛选和监视表筛选不影响计算；未采集到的错误、重发和流量不计入。接口自身过滤、丢帧或回显会影响估值。SocketCAN 的实际速率及不可解析的厂商自定义时序未知时不显示。
