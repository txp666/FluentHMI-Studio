# 链路、帧格式与 Modbus

[v0.9 使用手册](../guide.zh.md) · [UIDP 工程格式](../uidp-format.md)

每个设备放一张链路卡片，运行时在卡片上选择设备并点「连接」。同类卡片可以放多张。新建桌面卡片根据可见配置行自动确定高度，切换 `"完整"`、`"简洁"` 或串口的 `"单行"` 时重新整理高度。工程已保存的手动尺寸继续保留，普通属性修改不会强行收紧卡片。

连接错误使用应用内通知显示，卡片保留简短状态；同一卡片的相同错误在上一条通知显示期间不会反复叠加。通知中可以查看完整错误原因。

| 卡片 | 需要设置 |
| --- | --- |
| `SerialConfigCard` | `defaultPortName` 可预选串口，留空时在运行时选择。物理串口还需设置 `defaultBaud`、`defaultDatabits`、`defaultParity`、`defaultStopbits` |
| `TcpConfigCard` | `defaultMode` 为 `"客户端"` 或 `"服务端"`，`defaultHost` 是地址，`defaultPort` 为整数。网页作为 WebSocket 客户端，需要 WebSocket 端点或转接服务 |
| `UdpConfigCard`（桌面） | `defaultLocalPort` 是本地端口，0 由系统选择。`defaultHost` / `defaultPort` 是目标地址、端口。留空目标地址时，指定非零本地端口，收到数据后可以回复最后一个发送方。目标也可填广播地址 |
| `MqttConfigCard` | `defaultHost`、`defaultPort`、`defaultSubscribe`、`defaultPublish`，可选用户名、密码和 `defaultQos`（`"0"` / `"1"` / `"2"`）。订阅支持 `+` 和 `#` 通配符。网页连接 Broker 的 WebSocket 端点 |

桌面版可以在同一个运行工程的两张串口卡上分别选「虚拟串口 A」和「虚拟串口 B」，两端连接后双向传输。从串口收到的字节会走正常分帧、解析和绑定流程。工程内可用 `virtual:A` 和 `virtual:B` 预选端口。它们是应用内端口，波特率、校验位和流控只用于物理串口。[17.11 串口教程](../tutorials/17-frame-io.zh.md#1711-串口收发与数据发送卡)

桌面版在 MQTT 主题中把独立的 `{session}` 层级替换成本次运行的随机标识。同一工程的各张卡共用这个标识，运行卡片显示实际的订阅和发布主题。工程里的子通道绑定和发送目标填写原来的 `{session}` 形式，重开后自动对应新主题。[17.12 公共 Broker 教程](../tutorials/17-frame-io.zh.md#1712-mqtt-发布订阅与主题取值)

`serial.parser` 和 `serial.parserConfig` 是整个工程的帧格式。卡片的 `defaultParser` 为 `"项目设置"` 时直接使用它们。某张卡要单独分帧时指定解析模式和 `properties.parserConfig`。卡片的配置为空且解析模式与工程相同时沿用工程配置，其他模式使用各自默认配置。各个属性的选项和尺寸见[控件参考](../uidp-widgets.md)。

界面的「跟随工程」会标出实际解析模式。跟随 Modbus 时，角色、轮询周期或从站参数仍在卡片属性中编辑。独立的「帧格式」区域出现在可设置帧参数的文本或 HEX 模式。

## 工程帧格式模板

在「数据与报警 → 帧格式模板」新建一份 HEX 或文本／JSON 模板。用彩色样例核对帧格式和字段，保存后可在串口、TCP、UDP、MQTT 连接卡的「接收帧模板」中选用。也可以在工程属性的「默认帧格式」中选择模板，让使用工程设置的连接共用。

UIDP 1.3 用根对象 `frameTemplates` 保存定义，以 ID 为键。条目包含 `name`、`parser`（`"hex"` 或 `"line"`）、`parserConfig`，以及可选的预览 `sample`。`serial.receiveFrameTemplateId` 引用工程默认模板，连接卡的 `properties.receiveFrameTemplateId` 引用卡片模板。模板优先于该处的独立解析设置。模板重命名保留引用，删除前需先取消引用。

17 入门工程的转速模板如下。连接的接收模板和控件的发送模板都可以引用 `speed-frame`。数据点选择来源连接后从 `rpm` 读数，发送控件填写本次转速即可复用命令字默认值、长度及校验。

```json
{
  "frameTemplates": {
    "speed-frame": {
      "name": "转速帧",
      "parser": "hex",
      "parserConfig": {
        "header": "AA 55",
        "footer": "0D",
        "lengthOffset": 2,
        "lengthSize": 1,
        "lengthCovers": "数据",
        "checksum": "CRC16-Modbus",
        "checksumStart": 2,
        "checksumEndian": "小端(LE)",
        "fields": [
          ["cmd", 1, 1, "uint8"],
          ["rpm", 2, 2, "uint16", "小端(LE)"]
        ],
        "sendDefaults": {"cmd": "16"},
        "sendRequiredFields": ["rpm"]
      },
      "sample": "AA 55 03 10 DC 05 99 66 0D"
    }
  }
}
```

修改 HEX 模板的字段名称、类型或字节布局时，「应用帧格式」会先列出受影响的连接卡、工程数据点、显示控件、每条实时曲线和发送控件。选择「返回编辑」可继续调整。把 `rpm` 改为 `speed` 后，点「继续保存」会同步更新直接引用该模板字段的绑定。若控件的「全部匹配连接」涵盖不同帧格式，清单会标出该多来源绑定供核对。删除字段后，也可按清单检查相关绑定。

### 同一连接混收多种 HEX 帧

在连接卡的「接收帧模板」旁点「多选…」，勾选两份或更多 HEX 模板。选择单个模板时直接用卡片的下拉框。共用帧头时，可以贴入完整样例，点击命令字所在的字节，再点「用所选字节作命令字」。编辑器会同时填好其整帧偏移和 HEX 值。多字节命令可手动填写连续字节及起始偏移，偏移从整帧第 0 字节算起。帧头留空时，也可以用命令字识别。配置了两者的模板需要两处字节都匹配。组内任意两个模板应在某个共同检查的位置上有不同的字节值。

识别以后，按对应模板的固定长度、长度字段、帧尾或空闲间隔组帧，再验证该模板的校验值。用空闲间隔分帧的协议须在帧之间留出设定的间隔。在「解析预览」或「试解析」里粘贴一帧 HEX，预览会在已选模板中按帧头和命令字匹配，保留粘贴的内容，再显示解析和校验结果。手动切回另一模板时可以继续查看该模板原来的样例。

数据点、显示控件和曲线的「模板字段」以「模板名 · 字段名」显示。工程文件用 `模板ID.字段名` 取值。若字段名在组里唯一，原字段名也可取值。组内同名字段用模板限定名分别绑定。「多选」配置存为 UIDP 1.3 连接卡的 `properties.receiveFrameTemplateIds`，命令字设置存为模板的 `parserConfig.matchOffset` 和 `parserConfig.matchBytes`。发送控件各自选择发送模板。[三种模板混收示例](../tutorials/17-frame-io.zh.md#1710-同连接多接收模板)

在取值处选择「模板字段」即可绑定，也可以点「可视化取值…」核对字段。需要修改连接接收的模板时，使用「更改来源连接模板…」或到连接卡修改。影响清单会标出涉及的引用，确认后自动迁移仍由同一模板提供的字段。比如 17.10 将三种模板切成仅接收转速帧时，`speed.value` 会自动改为 `value`，温度和压力的字段会标记为不可用。

## 行文本和 JSON

`"line"` 默认 UTF-8 编码，以 LF 结束一条记录，逗号分项，等号分隔键和值。`temp=25.3,hum=60` 得到键 `temp`、`hum`。只有值的 `25.3,60` 得到 `ch0`、`ch1`。`separator`、`kvSeparator`、`terminator`、`encoding` 均可更改，编码可选 `utf-8`、`gbk`、`ascii`。记录两端会去除空白，默认也能接收 CRLF。

JSON 对象保留字段，顶层数组按 `"0"`、`"1"` 等键取值。完整的对象或数组可以跨行或连续发送，无需换行。以 `{` 或 `[` 起头的异常记录若在字符串外出现非法字节（如等号），解析器丢弃该行后继续。带 `*HH` 的 NMEA 语句先校验，合格的语句去除 `$` 和校验尾后按 CSV 解析。

MQTT 每条消息、UDP 每个数据报都自带边界。MQTT 若只收到一个数值，可直接用主题名当键，例如 `sensor/temp`。

## HEX 二进制帧

`"hex"` 下用 `parserConfig` 描述整帧。帧尾、长度字段、固定帧长、空闲超时至少配置一种。下面的工程片段让 `AA55 00 FD 55AA` 解析出键 `temp10`，其值为 253。

工程默认帧格式、连接卡和数据点的来源配置均可打开「可视化编辑帧格式」。左侧粘贴或生成示例报文，右侧修改帧头、帧尾、固定长度或长度字段、校验算法。点击彩色字节或字段行可相互定位，选中的字节也可作为新增字段的起点。彩色字节区的编号从帧首开始，新增字段的偏移从帧头之后起算。

编辑器标题下方显示修改范围。工程默认格式供跟随工程的连接使用。打开具体连接的编辑器并应用修改，会为该连接保存独立格式。工程数据点、控件绑定和曲线可在预览中选中字段，再点「使用所选字段」和「应用」，让连接解析一次供多处取用。文本解析也可通过样例选择字段或 JSON 路径。收发诊断中的「试解析」可单独检查现场样例。

配置长度字段后，样例用蓝色虚线标出计入长度的字节，范围按「长度含义」确定。当长度含义为「数据」时，长度字段之后、校验和帧尾之前的命令字也计入。启用校验后，橙色实线标出参与计算的字节，并按报文中的字节顺序对比「报文值」与「计算值」。例如报文 `AA 55 03 10 22 30 02 0D` 采用异或校验，起始字节设为 3，参与计算的是整帧字节 3–5 的 `10 22 30`，结果 `02` 位于字节 6。

```json
{"parser": "hex", "parserConfig": {
  "header": "AA55", "footer": "55AA",
  "fields": [["temp10", 0, 2, "uint16", "大端(BE)"]]
}}
```

| 帧参数 | 写法 |
| --- | --- |
| `header`、`footer` | HEX 字符串，默认 `"AA55"`、`"55AA"`。空字符串表示无帧头或帧尾 |
| `lengthOffset`、`lengthSize`、`lengthEndian`、`lengthCovers` | 长度字段偏移从帧头起算，默认 −1 表示无长度字段。长度占 1 或 2 字节，端序为 `"大端(BE)"` / `"小端(LE)"`，长度覆盖 `"数据"`、`"长度字段之后"` 或 `"整帧"` |
| `fixedLength`、`maxFrameLength` | 固定帧长（字节，默认 0）和变长帧总长度上限（默认 65536 字节） |
| `idleTimeout` | 组帧超时（毫秒）。空闲分帧以此确定结束位置，其他帧型在超时后丢弃未收齐的候选并尝试恢复后续完整帧。长度字段分帧设为 0 时，使用 1000 毫秒的空闲恢复时间。其他分帧方式设为 0 关闭超时 |
| `checksum`、`checksumStart`、`checksumEndian` | 校验算法可选 `"无"`、`"和校验"`、`"异或"`、`"CRC8"`、`"CRC16-Modbus"`、`"CRC16-CCITT"`。从帧内 `checksumStart` 偏移开始校验，校验字节紧贴帧尾之前 |
| `fields` | 每项为 `[键名, 偏移, 长度, 类型]`，可加第 5 项字节序。偏移从帧头之后算，类型含 `uint8/int8/uint16/int16/uint32/int32/float32/float64/ASCII/HEX` |

`fields` 产出的键可用「键值匹配」绑定。直接选「HEX字节提取」时拿到的是整帧，控件自己的剥头、剥尾和偏移规则见[取值与曲线](data.md)。

## 接收调试

数据接收卡的「自动显示」会把二进制报文显示为 HEX，文本按连接的编码显示。也可切换到「HEX」或「文本」，已有收发记录随显示格式重新渲染。每条记录独占一行，包含到达时刻、类型、内容和来源，长报文可以横向滚动。日志按 40 ms 定时批量更新，显示区按「最大行数」滚动保留最近记录。帧匹配、校验、取值和接收计数随报文处理。

已保存工程的运行预览和导出的应用会分别记住每张数据接收卡的「报文显示格式」「线路字节」和「自动滚动」，下次打开时自动恢复本机上次的选择。勾选「自动滚动」后，向上翻阅时暂停跟随，回到最底部时恢复。

开启「线路字节」后，卡片显示原始字节、组帧等待、丢帧原因和解析字段。点击一条报文或丢帧记录，再点「试解析所选」可核对这条样例及记录时的帧格式。直接点「试解析」会检查最近样例。HEX 预览指出帧头、整帧长度、帧尾或校验问题。文本与 JSON 预览显示字段和可用的路径。设计器中可从解析预览把选中的字段存为工程数据点。

## Modbus 主站与从站

| 模式 | 链路与设备行为 |
| --- | --- |
| `"modbus"`、`"modbus_tcp"`、`"modbus_ascii"` | 分别采用 RTU、TCP、ASCII 格式。读响应带 `slave`、`fc`，以及按响应内序号命名的 `reg0` 等寄存器或 `coil0` 等线圈。当读请求由本程序发出时，还带 `start` 和按地址命名的 `hr100`、`ir100`、`co100` 或 `di100` |
| 主站自动读取 | 卡片设置相应解析模式、控件、曲线或工程数据点绑定表区及地址，连接后开始轮询。`modbusPeriod` 默认 500 ms，`modbusTimeout` 默认 1000 ms，`modbusSlave` 默认 1。空接收连接沿用原有选卡规则，指定连接后在该卡上轮询 |
| 桌面模拟从站 | 串口、TCP 或 UDP 卡片设置 `modbusRole: "从站"`，帧格式选 RTU 或 TCP。`modbusSlave` 是本机地址，`modbusDelay` 是应答延时，设置 `modbusExceptions` 为 `false` 可忽略错误请求 |

桌面从站的每个区默认从地址 0 起，共 100 项，数量 0 表示该区为空。

| 表区 | 起始地址 | 数量 |
| --- | --- | --- |
| 线圈 | `slaveCoStart` | `slaveCoCount` |
| 离散输入 | `slaveDiStart` | `slaveDiCount` |
| 保持寄存器 | `slaveHrStart` | `slaveHrCount` |
| 输入寄存器 | `slaveIrStart` | `slaveIrCount` |

各项初值为 0，在 `slaveInit` 中每行写一项可设置初值，例如 `hr10=1234`。地址要落在该区配置的范围内。

TCP 服务端只轮询在线客户端。UDP 可以轮询已知对端或主动访问配置的地址。一次读取超时或收到异常响应时，对应连接、对端、从站及地址块的工程数据点标记为未知，等下次读取成功后恢复。

绑定、曲线或工程点匹配本地从站时，从该从站卡的表区取数。主站写入后控件刷新。开关、滑块和数值框未向外下发时，可按 Modbus 绑定写回唯一匹配的本地表。配置转换表达式的绑定只读。Modbus 命令也可更新其目标连接的本地表。`ModbusSlaveTable` 在「来源连接」中选择从站卡并用 `mbArea` 选择表区，留空时自动选用唯一匹配的从站卡。双击值可修改。
