**不兼容变更**：Modbus 卡片的轮询表删除了，`pollList`、`pollMode`、`autoStart` 三个属性不再存在，文件里写了也不起作用；绑定和实时曲线的寄存器区去掉了"响应内序号"，只剩保持寄存器（默认）、输入寄存器、线圈、离散输入，`mbRegIndex` 一律是寄存器地址。Modbus 绑定或 Modbus 曲线的 `mbArea` 写着 `"响应内序号"` 的工程打开时会报错（`控件 X 的 mbArea 只能是 保持寄存器、输入寄存器、线圈、离散输入`），旧工程请给绑定选寄存器区并填地址。Modbus 卡片变为可选：不放卡片也会自动轮询。

- Modbus 自动轮询：只要给控件绑定寄存器地址就会自动读取，不用放轮询卡片。程序按控件的 Modbus 绑定和实时曲线的 Modbus 曲线规划读取：同一从站、同一功能码里相近的地址合并成一块（寄存器间隔 ≤ 8、一块 ≤ 120 个，线圈和离散输入间隔 ≤ 64、一块 ≤ 1000 个），每块按绑定新增的「采集周期(ms)」（`mbPeriod`，0 用默认周期）读取，只读界面上看得见的控件，选项卡其他页上的不读。解析 Modbus 的链路能发送时（TCP 服务端要有设备连入）就开始，预览、FluentHMI Runtime 和导出的应用都一样。每条链路有一个 Modbus 主站队列，一次只有一个请求在线上，写命令排在读请求前面，按按钮写入不会再和在途的读请求撞车。没有卡片时默认周期 500 ms、响应超时 1000 ms，不过滤从站的绑定读从站 1。规划规则与 PyQt UI Designer 用同一份向量文件（`tests/data/poll_plan_vectors.json`）测试。
- Modbus 卡片是轮询的面板：工程里第一张卡片的「轮询ms」（运行时改了立即生效，0 按 500 ms）、响应超时和默认从站代替上面的默认值，其余卡片只显示状态，不会重复读。状态栏显示"N 块 · 轮询中"、"N 块 · 正常"、"第 k 块无响应（从站 S 功能码 F 地址 A）"、"第 k 块异常 02 非法数据地址"、"等待连接"、"没有 Modbus 绑定"或"已暂停"，鼠标悬停列出各块的从站、功能码、地址和周期；「停止」/「轮询」暂停和继续轮询（所有卡片共用）；「发送」随时可用，按字段发一条请求，轮询时结果以通知显示，暂停时写在状态栏。
- 应用标识改为 `io.github.txp666.FluentHMIStudio` / `io.github.txp666.FluentHMIRuntime`（导出的应用为 `io.github.txp666.fluenthmi.app…`）。macOS 会把新版当成一个新应用，偏好设置会重置一次。
- 串口 / TCP / MQTT 配置卡片只保留一个「连接/断开」按钮（连接中显示「取消」），放在最后一行字段的右端，不再单占一行；默认尺寸改为串口 360×320、TCP 360×250、MQTT 380×390。卡片不会再比内容矮：运行时按字段需要的高度显示，设计器按内容限制最小高度（拖拽、属性面板、切换显示方式时都一样），打开旧工程时太矮的卡片会抬到放得下字段的高度。
- 示例 `examples/tutorials/02-温控仪监控.uidp` 和 `10-PLC恒压供水.uidp` 不再放 Modbus 卡片，界面重新排了版，都靠自动轮询读取：02 的四个 Modbus 绑定选了保持寄存器，和两条曲线合成一块（保持寄存器 0–5），10 读三块（线圈 0–3、保持寄存器 100–105 和 200–201），周期都是默认的 500 ms。
