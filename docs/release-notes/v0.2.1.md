**不兼容变更**：删除 Modbus 配置卡片（`ModbusConfigCard`），含它的旧工程需手工删掉该控件（打开时报 `未知控件类型: ModbusConfigCard`）；轮询参数改在链路卡片上。卡片的轮询表（`pollList`、`pollMode`、`autoStart`）、「停止」/「轮询」和「发送」随卡片一起去掉：轮询总是自动进行，手动读写寄存器用按钮、输入框、开关等控件的 Modbus 发送模式。绑定和实时曲线的寄存器区去掉了"响应内序号"，只剩保持寄存器（默认）、输入寄存器、线圈、离散输入，`mbRegIndex` 一律是寄存器地址。Modbus 绑定或 Modbus 曲线的 `mbArea` 写着 `"响应内序号"` 的工程打开时会报错（`控件 X 的 mbArea 只能是 保持寄存器、输入寄存器、线圈、离散输入`），旧工程请给绑定选寄存器区并填地址。

- Modbus 自动轮询：链路卡片选 Modbus 解析、控件绑定寄存器地址即可自动读取。程序按控件的 Modbus 绑定和实时曲线的 Modbus 曲线规划读取：同一从站、同一功能码里相近的地址合并成一块（寄存器间隔 ≤ 8、一块 ≤ 120 个，线圈和离散输入间隔 ≤ 64、一块 ≤ 1000 个），每块按绑定新增的「采集周期(ms)」（`mbPeriod`，0 用链路卡片的默认轮询）读取，只读界面上看得见的控件，选项卡其他页上的不读。解析 Modbus 的链路能发送时（TCP 服务端要有设备连入）就开始，预览、FluentHMI Runtime 和导出的应用都一样。每条链路有一个 Modbus 主站队列，一次只有一个请求在线上，写命令排在读请求前面，按按钮写入不会再和在途的读请求撞车。规划规则与 PyQt UI Designer 用同一份向量文件（`tests/data/poll_plan_vectors.json`）测试。
- 串口 / TCP / MQTT 配置卡片新增三个属性：「默认轮询(ms)」（`modbusPeriod`，默认 500）、「响应超时(ms)」（`modbusTimeout`，默认 1000）和「默认从站」（`modbusSlave`，默认 1，给不过滤从站的绑定用），属性面板里只在卡片的解析模式选了 modbus / modbus_tcp / modbus_ascii 时显示。轮询用链路已连上并解析 Modbus 的卡片的设置，有几张时用文档里的第一张，没有时用这三个默认值。链路能发送的这类卡片（TCP 服务端要有设备连入）在状态栏的连接信息后面显示轮询状态（串口卡片的单行模式显示在按钮右边，单行模式原来没有状态）："N 块 · 轮询中"、"N 块 · 正常"、"第 k 块无响应（从站 S 功能码 F 地址 A）"、"第 k 块异常 02 非法数据地址"或"没有 Modbus 绑定"，鼠标悬停列出各块的从站、功能码、地址和周期。
- 应用标识改为 `io.github.txp666.FluentHMIStudio` / `io.github.txp666.FluentHMIRuntime`（导出的应用为 `io.github.txp666.fluenthmi.app…`）。macOS 会把新版当成一个新应用，偏好设置会重置一次。
- 串口 / TCP / MQTT 配置卡片只保留一个「连接/断开」按钮（连接中显示「取消」），放在最后一行字段的右端，不再单占一行；默认尺寸改为串口 360×320、TCP 360×250、MQTT 380×390。卡片不会再比内容矮：运行时按字段需要的高度显示，设计器按内容限制最小高度（拖拽、属性面板、切换显示方式时都一样），打开旧工程时太矮的卡片会抬到放得下字段的高度。
- 示例 `examples/tutorials/02-温控仪监控.uidp` 和 `10-PLC恒压供水.uidp` 不再放 Modbus 卡片，界面重新排了版，都靠自动轮询读取：02 的四个 Modbus 绑定选了保持寄存器，和两条曲线合成一块（保持寄存器 0–5），10 读三块（线圈 0–3、保持寄存器 100–105 和 200–201），周期都是链路卡片默认的 500 ms。
